## Editing And Important Existing-Rule Boundary
Exercise and food/meal substitutions are executable, constrained to compatible
catalog choices. Reps1..12 use the existing validator. The existing set rule is
FIXED: beginner2, regular3. Direct sets input exists but an unsupported count is
explicitly refused atomically; the previous complete draft stays unchanged.
Changing the explicit experience and rebuilding can select the other existing
catalog set rule. This is NOT unrestricted per-exercise set editing. A wider range
needs a separately approved versioned rule; this package does not invent one.

Days, preferences, units or other intake edits create a new intake snapshot and
invalidate the prior draft/confirmation. An active plan/history remains unchanged
until new review, member confirmation and separate activation. Successful draft
edits also invalidate confirmation. Rejection cannot activate.

Activation commits a whole immutable bundle; injected precommit failure changes
nothing. Identical requests/duplicate confirmation are idempotent; a second
activation cannot create another version. Stale bindings fail with no partial plan.
Restore proposes an old plan under CURRENT consent, safety, sources and exclusions,
then requires new confirmation and separate activation. It makes a new monotone
version without deleting old snapshots. Incompatible old plans remain blocked.
