## Scope And Data Flow

1. Operator provisions a bounded synthetic window, identities and purpose/expiry.
   The trusted role/link mechanism remains the existing 6D-0 model; no client
   admin switch or broad editable role metadata.
2. A linked synthetic trainer manages ONLY own member A's fictional exercise
   identity, kg/lb unit, rep range, exact weight step, set count and optional
   separate RIR/RPE boundaries. No default invented progression or medical norm.
3. A source edit appends a new immutable revision. A server validator reports
   missing/conflicting values, W1 ambiguity, W2 non-fitting steps and stale links.
4. The deterministic planner cites exact goal/schema/rule revisions. Existing
   approvals do not transfer. Member acceptance, trainer approval and separate
   apply still use the 6E-9 atomic/version/idempotency boundary.
5. Route B remains independently eligible and uses a separately versioned
   controlled synthetic catalog; no trainer approval or silent fallback.
6. Expired windows lose access immediately. An idempotent cleanup process removes
   only tracked synthetic identities/fixtures and produces aggregate deletion
   evidence; failed cleanup is visible for operator retry. No clinical queue.

  A menu inside the normal application is OUT of scope; retain separate entry.
- New narrow Edge source commands with server actor/route derivation, bounded
  enum/numeric payloads, no private free text or service credential in browser.
- Potential later additive migration: dedicated versioned synthetic source/rule
  records, window lifecycle/cleanup receipts and narrow transaction functions.
  Exact names/CLI migration identity are determined only after GO.
- RLS/ACL: own linked trainer can manage A rule sources through guarded commands;

  lifecycle must be designed/tested before enabling unattended windows. Avoid
  claiming a timestamp access check is physical deletion.

- Existing A/B approval and restore chains remain unchanged; applying cannot
  partially commit and concurrent source change invalidates stale approval.
- Historic rule/schema content remains immutable and reproducible.
- Test expiry at boundary, failed cleanup/retry, no renewal by reads/retries,

- Updated negative REST/RPC/RLS proof, both-route browser review, 60 application
