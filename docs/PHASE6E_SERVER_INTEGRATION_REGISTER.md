## Common Security And Test Gates

Authenticated server identity is necessary but insufficient: verify live session,
synthetic participant/window, route, relationship, consent, source/rule versions
and scoped operation. Do not use editable user_metadata or a service key in the UI.
No real-member rows may be admitted as synthetic test fixtures.

Every action requires prior allowed INSERT/UPDATE/DELETE rows, exact transaction
witness and sealed scoped before/after pair. Unexpected/missing writes block the
next action and cleanup. Preserve deletes in audit. No heavy whole-database scan
after each action. A final stable protection check remains necessary; metadata
counts are not its replacement.

Auth generate_link/verify/refresh/logout/control-create/control-delete need
separate proven synthetic routes. Unprovable optional account routes remain
technically excluded. No global owner/member logout, unproven cascade or
management writes to managed Auth tables.

For each slice: restart/refresh/relogin; cross-member/route denial; expiry/revocation;
missing/conflicting source; same-key replay versus changed payload; concurrent
version conflict; fault after each write; exact old/new immutable history;
approved restoration as NEW version; scoped delete and protected-data preservation.
Notification work is a later transactional in-app outbox, never a claim that a
browser-memory card already runs in the background.

Rollback: disable the new synthetic entry first, preserve evidence and histories,
then restore an eligible earlier choice through a new version with fresh required
approvals. Delete only owned temporary fixture IDs after complete audit pairs.
No destructive downgrade, migration-history rewrite or frozen-source replacement.
